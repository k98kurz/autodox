## 0.2.0 (WIP)

- Breaking change: the CLI now uses GNU-style `--long-name` options instead of
  the previous single-dash `-long_name` options (e.g. `--exclude-name` replaces
  `-exclude_name`); help is generated by `argparse`, so run `autodox --help` for
  the updated usage
- `--debug` output now uses the standard library `logging` module and is written
  to stderr, so it no longer contaminates markdown redirected from stdout;
  levels 1-3 still select the same traces as before
- Names (annotations, values, classes, modules, and aliases) and types
  (annotations and values) are now rendered as inline code (backticks) by
  default; module headers, which were previously plain, are quoted as well
- Added `backtick_names`, `backtick_types`, and `backtick_signatures` options
  (on by default) and the corresponding `--no-backtick-names`,
  `--no-backtick-types`, and `--no-backtick-signatures` CLI flags to disable
  each category
- Added a `backticks` option and `--no-backticks` CLI flag that disable all
  backtick quoting at once, even for categories the granular options leave on
- Added a `-v` / `--version` CLI flag that prints the package version and exits
- Module-level type aliases now render their definitions in the Values section
  as `Name = Type` instead of their private runtime class name (e.g.
  `_CallableGenericAlias`); PEP 585 builtin generics, PEP 604 unions, `typing`
  aliases, and PEP 695 `type` aliases are supported
- `typing.NewType` values now render as `Name = NewType('Name', Supertype)`
  instead of `Name: NewType`
- Functions and methods wrapped by decorators exposing `__wrapped__` (e.g.
  `functools.lru_cache` and `functools.cache`) are now documented with their
  real signatures and docstrings instead of appearing as values; cached
  methods are no longer omitted, and classes wrapped by such decorators are
  documented as classes instead of values
- Async static methods now include the `async` marker, including when wrapped
  by `functools.lru_cache` or `functools.cache`; wrappers around
  `classmethod` retain the `@classmethod` marker and no longer show an
  implicit `cls` parameter
- Added a `clean_type_aliases` option and `--no-clean-type-aliases` CLI flag to
  keep module qualifiers in rendered type alias definitions; cleanup is on by
  default and never rewrites string literals such as `Literal['typing.Foo']`
- `dox_a_value` accepts a `module_name` option specifying the module qualifier
  to strip from type alias definitions (set automatically by `dox_a_module`)
- Fixed PEP 585 aliases such as `list[int]` being documented as classes on
  Python 3.10

## 0.1.17

- Bug fixes:
  - Class, function, and method aliases are now detected automatically and
    documented as `Alias = Target` instead of appearing as duplicates of the
    target
  - Function and method signatures now render the full parameter list in
    declaration order with correct defaults, `*args`/`**kwargs` markers,
    properly placed `/` and `*` separators, and preserved `None`/subscripted
    (e.g. `dict[str, str]`) annotations
  - Class annotations now respect `include_private`, `include_dunder`, and
    `exclude_names` instead of always being documented
  - Annotation types render as `int`/`dict[str, str]` instead of
    `<class 'int'>`, matching function signatures
  - Name-mangled private annotations and properties are displayed under their
    source names (e.g. `__hidden` instead of `_Class__hidden`), and
    `exclude_names` accepts either form
  - The `dox_a_*` functions' `options` parameter now defaults to `None`
    instead of a shared mutable `{}`, preventing a `BEFORE_` handler that
    mutates `options` in place from leaking state into later calls
